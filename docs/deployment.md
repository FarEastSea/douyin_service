# 部署与恢复

## 简要部署指引

常见部署方式如下：

1. 准备 Python 3.11 或 3.12、PostgreSQL 和 Redis。
2. 安装项目依赖并提供基础运行参数。
3. 使用 uvicorn、systemd、supervisor、容器或现有进程管理方式启动服务。
4. 通过反向代理暴露 Web 管理页面和 API。
5. 首次进入管理页面后完成 Cookie 和运行参数配置。

如果当前环境仍沿用仓库脚本，可参考 [start.sh](../start.sh) 和 [stop.sh](../stop.sh)。这两个脚本适用于 Linux 环境；Web 关闭不会终止项目级 Worker 与 Beat，`stop.sh` 会核验身份并显式停止。启动使用 `uvicorn-worker` 提供的 Gunicorn worker。

生产运行以宝塔面板中的项目配置和统一 Python 环境为基线，项目根目录是唯一运行代码目录。宝塔中的项目路径、入口文件 `main.py`、依赖文件 `requirements.txt`、ASGI 应用名 `app` 和 `.env` 路径均保持指向项目根目录，不使用 `.current` 或版本目录作为运行入口。

Jenkins 用宝塔运行环境的同一 Python 解释器建立全新候选环境，解析并构建依赖 wheel 制品，执行 `pip check`、导入和前端资源完整性检查。候选预检只读，不执行数据库迁移；预检通过后保留原依赖制品，进入维护模式、停止新投递、排空旧队列并停止旧 Web、Worker 与 Beat。随后以 `pg_dump` 创建并校验 PostgreSQL 备份，才执行正式迁移。生产安装使用候选验证过的同一 wheel 制品和解析版本，校验 SHA256，不重新联网解析依赖。版本查询保留在网页，直接在线拉取代码入口已停用，发布统一经过此流程。

排空允许最长两小时的既有存储任务完成；订阅检查在作者之间保存断点并暂停，发布结束后继续检查。首次升级的旧 Worker 若已投递自动续检，只在参数与数据库断点完全一致时延后该续检，并等待消息正常确认；不会终止活动任务或清空队列。排空阶段协调持续失败会提前中止；未切换代码时经旧 Web 的管理协议恢复服务，禁止用候选解释器启动旧代码。

发布会保存并暂时关闭宝塔中该项目的自动重启和启动意图，停止入口后持续核验独占状态。新旧版本均通过同一个宝塔项目入口启动；验收完成后恢复原守护设置。网页初始化和配置恢复在维护期等待，避免外部重启干扰迁移。就绪接口同时返回 Web 装载时冻结的代码、依赖和进程身份；验收不能只比较磁盘版本。发布阶段记录在 `.runtime/deployment-status.json`，未完成的所有权交接保留恢复清单。

数据库归档附带 SHA256、结构、迁移台账、行数和序列状态清单。恢复前检查归档完整性，恢复事务内核验基线，提交后再检查一次；任何不一致均停止恢复或保留维护状态。没有有效清单的历史归档不会被自动恢复，原文件仍保留。

切换后验证首页、文档、数据库/Redis、统一任务、作者、平台验收矩阵、只读存储巡检以及已有媒体的预览和 Range 请求。没有真实成功媒体的平台保留“待首次验收”。失败会先停止新入口和后台进程，再恢复迁移前的数据库、旧代码及旧依赖；恢复在单一事务中清理迁移新增对象并导入备份，失败不会留下半恢复状态。若进程无法停止或恢复失败则保留维护模式和备份，禁止把代码回滚当作数据库已恢复。备份与依赖恢复制品保存在被忽略的 `.runtime/deploy-recovery/`。服务器需具有匹配 PostgreSQL 版本的 `pg_dump`、`pg_restore` 和 `psql`；只读预检会提前核验恢复角色的数据库 CREATE 权限和应用 schema 管理权限。宝塔环境目录继续由 Jenkins Secret text 凭据 `douyin-remote-python-env` 提供，可使用包含 `bin/python`、`bin/gunicorn` 的环境根目录或对应 `bin` 目录，启停和发布脚本会统一解析。

账号密钥保存在项目根目录的 `.runtime/douyin-account.key` 和 `.runtime/platform-credentials.key`，不会提交到 Git，也不会被 Jenkins 的代码切换覆盖。备份账号数据库时必须同时备份这些密钥；密钥丢失后，需在设置中心重新填写对应 Cookie 和已启用的代理地址。
