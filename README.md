# 媒体下载管理系统

媒体下载管理系统是一个面向日常下载运营场景的管理服务，提供抖音作品下载、作者订阅巡检、任务管理、媒体预览，以及 X/Twitter 下载链路。项目同时提供 Web 管理界面和 API，适合用于持续下载、集中管理和简单排查。

## 功能特性

- 支持抖音单作品下载与作者主页批量下载。
- 支持视频与图集下载，图集可拆分为独立图片任务。
- 支持任务暂停、恢复、重试、强制重试、删除和批量重试。
- 支持已完成视频和图片的本地预览，未完成图片可回退使用源地址预览。
- 支持作者订阅、自动巡检新作品，以及从作者视图联动查看相关任务。
- 记录作品封面、时长、分辨率、音乐、话题和互动数据，并保留互动统计变化快照。
- 提供 X/Twitter 下载链路与配套管理能力。

## 配置基调：网页配置是唯一权威来源

- 所有可配置项都必须在 Web 设置中心提供配置入口；部署环境文件只承担首次启动和持久化载体职责。
- 业务代码每次使用配置时都必须读取网页最新保存值，禁止读取后复制到常量、模块缓存或硬编码分支中长期使用。
- 网页配置的优先级绝对高于进程环境变量、代码默认值和历史缓存；代码默认值只允许用于首次初始化。
- 配置变更后，下载、订阅检查、任务调度、媒体预览和 X/Twitter 链路必须在下一次操作时平滑使用新值。
- 下载目录采用“统一根目录 + 平台子目录”，例如 `/downloads/douyin` 与 `/downloads/X`；修改时系统会保留相对路径，并同步迁移已有任务、历史和 X 资源记录中的持久化路径。
## 技术栈

- FastAPI
- SQLAlchemy 2.x
- PostgreSQL
- Redis
- Celery
- Web 管理界面

## 运行环境

- Python 3.11 或 3.12
- PostgreSQL
- Redis

当前部署环境实际使用 PostgreSQL。代码层保留了 MySQL 支持，但不是当前项目的实际使用形态。

## 快速开始

### 安装依赖

```bash
python -m venv .venv
```

Windows:

```bash
.venv\Scripts\activate
```

Linux:

```bash
source .venv/bin/activate
```

```bash
pip install -r requirements.txt
```

### 启动服务

```bash
uvicorn main:app --host 0.0.0.0 --port 8000
```

也可以直接运行：

```bash
python main.py
```

启动后可访问：

- 首页：/
- Swagger 文档：/docs
- ReDoc：/redoc

应用启动时会自动初始化数据库，并自动拉起 Celery Worker 和 Beat。

### 首次使用

首次启动引导完成后，所有配置统一通过 Web 设置中心维护，包括数据库、Redis、下载目录、Cookie、订阅巡检、下载参数和 X/Twitter 链路配置。网页保存值是运行时唯一权威来源。

X 下载按作者保存到 `<下载根目录>/<X 子目录>/<用户名>/`。每个图片或视频会建立独立资源记录，可在 X 任务列表中逐项预览或下载。X 当前要求有效 Cookie；下载器使用持久化归档避免重复获取，并内置请求间隔、429 冷却和有限重试。

## 简要部署指引

常见部署方式如下：

1. 准备 Python 3.11 或 3.12、PostgreSQL 和 Redis。
2. 安装项目依赖并提供基础运行参数。
3. 使用 uvicorn、systemd、supervisor、容器或现有进程管理方式启动服务。
4. 通过反向代理暴露 Web 管理页面和 API。
5. 首次进入管理页面后完成 Cookie 和运行参数配置。

如果当前环境仍沿用仓库脚本，可参考 [start.sh](start.sh) 和 [stop.sh](stop.sh)。这两个脚本适用于 Linux 环境，且默认由应用自身管理 Worker 与 Beat。

生产运行以宝塔面板中的项目配置和统一 Python 环境为基线，项目根目录是唯一运行代码目录。宝塔中的项目路径、入口文件 `main.py`、依赖文件 `requirements.txt`、ASGI 应用名 `app` 和 `.env` 路径均保持指向项目根目录，不使用 `.current` 或版本目录作为运行入口。

Jenkins 使用项目根目录下被忽略的 `.venv` 作为独立预检环境：先在系统临时目录解包候选提交，安装依赖并完成后端导入、数据库迁移和前端资源完整性检查。候选代码通过后，Jenkins 会自动在宝塔统一环境中安装 `requirements.txt` 并再次执行依赖一致性和项目导入校验；任何依赖失败都发生在停止旧服务之前。随后 Jenkins 停止根目录及历史 `.current` 入口的旧实例，将根目录切换到目标提交，并立即由 `start.sh` 直接调用宝塔环境的 `bin/gunicorn`，无需人工启动或等待宝塔守护检查。首页、文档、任务、作者或媒体预览检查失败时，会回退根目录提交并立即重启上一版本。旧 `.current` 与 `.releases` 布局会在首次成功迁移后清理。宝塔环境目录由 Jenkins Secret text 凭据 `douyin-remote-python-env` 提供，值为包含 `bin/python` 和 `bin/gunicorn` 的环境根目录。

## 开发说明

当前依赖组合在 Python 3.14 下存在兼容性问题，已确认 sqlalchemy==2.0.25 在该版本下无法正常导入。本地开发和调试建议统一使用 Python 3.11 或 3.12。
